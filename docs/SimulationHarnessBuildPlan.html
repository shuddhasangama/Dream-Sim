Simulation Harness — Build Plan

Run the product's logic on your laptop with synthetic users, before the app exists. Validates mechanics, tunes agents, and answers the minimum-viable-pool question empirically.

The critical split

What you can build yourself, now: a local simulation of the product's logic — synthetic users, matching + REACH math, the weekly cadence, agents narrating, use cases executing. Pure Python. No mobile, no app store, no real BGV, no payments.

What needs the CTO: the actual app — cross-platform mobile, auth, hosted backend, real BGV integration, payments, push, store submission, scale. A 3–5 month build for a CTO plus one or two devs.

Why build this before the app

  • The spec already exists. 127 use cases with Given/When/Then and Gherkin files, the full-journey build brief's data model, and five agent specs with I/O contracts. The harness has something real to build against.
  • Answers the minimum-viable-pool question — sweep from 20 to 500 users per city and watch when the weekly cadence starts producing honest 2–3 match weeks. An empirical launch gate instead of a guess.
  • Proves the REACH reciprocity math behaves sensibly before real users see it.
  • Tunes agent prompts on realistic inputs, before production.
  • Becomes an executable spec for the CTO — they start building on day two instead of week three.

The build sequence

1Environment

Python 3.11+, Claude Code installed, Anthropic API key set, a git repo. Effort: half a day.

2Data model

Translate the build brief's entities (User, Couple, CalendarEntry, Difference, WeeklyReport, Exit, Invite) into SQLite. Claude Code generates this well directly from the brief. Effort: 1–2 evenings.

3Synthetic user generator

50 users across your age bands, gender, and metro cities, with Vision / Stats / preferences drawn from realistic distributions. Seeded and reproducible. Effort: 1–2 evenings.

4Deterministic core — no LLM yet

Matching, REACH reciprocity counts, the weekly cadence (staggered reviews, midday close, mutual lock-in). This is the bulk of the value and it is all plain logic. Effort: 1 week.

4½Walk the journey yourself

A simple CLI to act as a user — play as a male user and a female user, progress stage by stage, feel what's wrong. Do this before automating tests. Manual play surfaces UX and logic problems automated suites never catch. Effort: 2–3 evenings for the CLI, then ongoing play.

5Scenario runner

Wire in usecases.json / the Gherkin .feature files so all 127 cases execute as a test suite. Effort: 3–5 evenings.

6Layer the agents on

The five starter prompts calling the Claude API for narration — REACH's read, Guru's pillars, the weekly report. Effort: 3–5 evenings.

7Metrics & report output

Locked-in dates per city per week, match counts, funnel drop-offs, failed invariants. Effort: 2–3 evenings.

8Sweep experiments

Vary pool size, gender ratio, filter narrowness. The minimum-viable-pool answer falls out here. Effort: cheap and ongoing once the harness exists.

Cost note: most of the simulation needs no LLM at all. Matching, reciprocity and cadence are deterministic. Only agent narration calls Claude. Build steps 1–4 first and run thousands of simulated weeks for free; layer API calls on afterward and token spend stays modest.

What this will NOT tell you

  • It validates mechanics, not demand. Synthetic users behave as instructed. It cannot tell you whether real Bangalore 32-year-olds will sign up, complete BGV, or pay for a date.
  • The pool number will be directional, not precise — it rests on assumed filter distributions. Read it as "roughly 200, not 20," never "exactly 187."
  • It does not replace the pre-launch feedback work with real people.

Timeline flag

CTO landing in September and India matching live on December 11 is roughly three months for a full-stack marketplace with BGV, payments, five LLM agents, across two platforms. That is aggressive. The harness genuinely de-risks it — a CTO walking into working logic plus 127 executable test cases starts fast — but go into that hire with the timeline pressure named openly.
