# Profile templates, optional disclosures and portraits

## Installed app
- Guided signup now has Vision, Stats, Chemistry, then optional Profile.
- Home's Vision editor offers Grow Together, Two Together, Explore Together and BYOB.
- Templates replace the actual pillars only after Save Vision. Physical intimacy is a preference, never consent. Grow uses the existing Naturally/Physical prerequisite; BYOB allows other routes.
- Template changes are refused during live matches, keenness or a relationship. Existing pair progress is never reset.
- Legacy per-pillar changes mark an existing template as customised and keep future-children intent consistent.
- Two Together means no additional children. Existing children remain a separate field.
- Home > Photo, ethnicity & health preferences opens the same Profile editor.

## Disclosure and matching
- Ethnicity: optional, maximum two, distinct from nationality, no ethnicity matching filter.
- Health/accessibility categories and note are optional, self-declared and shown to revealed candidates only with explicit consent. Do not use actual patient data for synthetic test profiles.
- Private openness preferences filter future ordinary matching reciprocally. All disclosed categories must be accepted in specific mode. Unknown/undisclosed is a separate inclusion choice, never an assertion of good health.
- Categories are not a diagnosis or a clinical severity assessment. Notes are not parsed for matching.
- Withdraw by clearing the note/categories, unchecking consent and saving. Previously viewed information cannot be recalled.
- Already published matches, active pairs and operator-assigned synthetic test pairs are not regenerated by changing preferences.
- Consent withdrawal stays possible while matching preferences are locked.

## Photos
- Select JPEG/PNG/WebP, adjust zoom and position, preview, then Save portrait.
- Server validates the image, strips metadata and stores a 480x600 JPEG in ProfilePhoto (database-backed; no ephemeral Railway filesystem dependency).
- Photos are delivered in authenticated own-profile/revealed-match responses, not at a public URL. Remove photo deletes the stored row.
- A photo is not identity/BGV/biometric verification. Native camera capture is not implemented; the system image picker is used.

## Deployment
1. Commit/push changes. Railway installs Pillow from requirements.txt and creates ProfilePhoto through the existing schema initialization.
2. Verify Railway deployment health.
3. Build/distribute updated Android and iOS apps through Codemagic.
4. Test with synthetic accounts: template selection, custom Vision, dual ethnicity, disclosure consent/withdrawal, preferences, portrait crop/save/remove, revealed match panels.
No new Railway variables, no reset scripts, and no changes to OTP-free tester entry.

The browser preview is a local UI mock. Backend tests cover validation/privacy/matching. Native-device upload permissions and presentation must also be checked on iOS and Android after installing the build.
